## 5. 남는 흐름 — 이게 전부다

```
사건 만들기 → 사고 설명(글) → 영상 올리기 → 분석(로딩)
  → 영상 분석 요약(글) → 부족하면 AI가 글로 질문 · 사용자가 글로 답
  → 예상 과실비율(비율 · 한 줄 결론 · 근거 목록)
  → 사건경위서 초안 → 전문 보기 → PDF 받기
  → 반박의견서 초안 → 고치기 → 발송 확인 → 발송 완료 → 다음 할 일
```

되돌아가는 길(재판정·사실 고치기·이력)은 없다. 대화는 **앞으로만** 간다.

## 6. 코드에 미치는 영향

**`ChatMessage` 종류 15 → 10**

남는다: `text`(user·ai) · `video` · `guide` · `uploading` · `analyzing` · `verdict` · `statementDraft` · `rebuttalDraft` · `sent` · `nextSteps`
없앤다: `facts` · `question` · `choice` · `rejudging` · `error`(발송 실패는 팝업으로만)

**없어지는 것** — `FactsCard` · `QuestionCard` · `RejudgingCard` · `ErrorCard` · 인라인 사실 편집기 · `ChartDialog` · `HistoryDialog` · `countConfirmed()` · `Fact` 출처 태그 · 상대 주장 입력 폼 · 재판정 관련 상태 전부.

**남되 줄어드는 것** — `VerdictCard`(파란 박스 제거 · 9/6에 비교 막대만 되살림) ·
`AnalyzingCard`(단계·멈추기 제거 · 9/6에 서류 작업까지 맡는다) · `StatusPanel`(이력 제거 · 9/6에 사실 칩 되살림) · `StatementDialog`(대화 수·쟁점 캡션·**절별 근거 줄** 제거, [다시 쓰기]는 유지) · `StatementDraftCard`(대화 수·쟁점 캡션 제거) · `UploadingCard`(실패·취소 상태 제거) · `CaseRow`(⋯ 메뉴의 [변경 이력] 제거) · 온보딩 `VerdictMock`(일치도·도표 [보기] 제거).

**`StatementSection`에서 `sources`가 빠진다** — 절은 제목과 본문만 갖는다.

**AI 응답 계약이 바뀐다** — 분석 결과를 항목 배열이 아니라 **글**로 받는다.

**9/6에 늘어난 계약** (자세한 것은 `05_프론트_수정요청.md`)

- `Case.facts` — `{ confirmed, total, label, items[{label, source}] }` 또는 `null`. `case.updated`로 함께 온다
- `Verdict.opponentClaim` — 상대 주장 비율 또는 `null` · `Verdict.opponentClaimNote` — 견주는 한 줄(**항상 온다**)
- `Verdict.chartName` — 번호가 **앞머리에 실려 온다**("266 · 차대차 회전교차로 사고"). 화면이 번호를 따로 그리지 않는다
- 서버가 보내는 모든 글에 **문장 끝 줄바꿈**이 들어 있다 — 글자를 그리는 곳에 `whitespace-pre-line`
- 다시 쓴 서류와 갱신된 판정은 `message.updated`로 온다 — 같은 id를 교체하고 **대화 끝으로 옮긴다**
